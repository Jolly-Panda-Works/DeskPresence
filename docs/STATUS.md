> آخرین به‌روزرسانی: ۲۰ اکتبر ۲۰۲۶ — برای ادامه کار در آینده.
> مخزن: [Jolly-Panda-Works/DeskPresence](https://github.com/Jolly-Panda-Works/DeskPresence) — سازنده: Usef Farahmand

## خلاصه در یک نگاه

| بخش | وضعیت | کجاست |
|---|---|---|
| نرم‌افزار ویندوز | **منتشر شده، پایدار** — آخرین نسخه v1.7.29 | برنچ `main` |
| برنامه اندروید | ساخته شده، در CI کامپایل شده (APK در v1.6.27)، **روی گوشی واقعی تست نشده** | برنچ `mobile-app` |
| سرور روی کامپیوتر (companion) | ساخته و تست خودکار شده | برنچ `mobile-app` |
| سرور واسط (relay) برای بیرون از خانه | ساخته و تست خودکار شده، **روی سرور نصب نشده** | برنچ `mobile-app`، پوشه `relay/` |

## ۱. نرم‌افزار ویندوز (برنچ `main`)

### قابلیت‌ها

- **تشخیص حضور:** وبکم (YuNet)، گوشی از طریق بلوتوث، یا هر دو؛ اگر هیچ‌کدام در دسترس نباشد، بی‌کاری کیبورد و موس.
- **بلند شدن از پشت میز:** شمارش معکوس روی همه مانیتورها و تاریک شدن تدریجی صفحه (با نگاه به دوربین یا حرکت موس لغو می‌شود، کلیک از رویش رد می‌شود)، بعد توقف آهنگ و ویدئو، خاموش کردن مانیتورها (کامپیوتر روشن می‌ماند)، قفل اختیاری. **برگشتن:** روشن شدن مانیتور و پخش دوباره فقط آهنگ (ویدئو متوقف می‌ماند).
- **برنامه‌های آهنگ و ویدئو:** تشخیص خودکار (Spotify، رادیو جوان، YouTube، Media Player و …) با امکان تغییر دستی.
- **تماس تلفنی:** با Phone Link ویندوز، هنگام تماس آهنگ و ویدئو متوقف می‌شود.
- **موس:** پرش به مانیتوری که به آن نگاه می‌کنید (چرخش سر)، یا دنبال کردن چشم (MediaPipe، کالیبراسیون ۵ نقطه روی هر مانیتور، Ctrl+Alt+E).
- **سلامتی:** یادآوری آب با دکمه «خوردم» و «۱۰ دقیقه دیگر»، استراحت اجباری بعد از ۹۰ دقیقه (تایمر فقط وقتی پشت میز نیستید جلو می‌رود)، یادآوری بلند شدن.
- **تایمرها:** فقط زمان پشت میز را می‌شمارند؛ دوری کوتاه آن‌ها را متوقف می‌کند، دوری بیش از ۱۰ دقیقه و sleep/hibernate آن‌ها را ریست می‌کند.
- **ویجت:** همیشه رو، قابل جابه‌جایی، کوچک‌شدنی به یک خط، قابل بستن، شفافیت ۳۰٪ تا ۱۰۰٪.
- **اشتراک وبکم:** وقتی برنامه تصویری (Zoom، Teams، Camera، OBS، …) باز شود می‌پرسد و وبکم را می‌دهد و بعد پس می‌گیرد؛ دکمه آزاد کردن دستی.
- **اتصال لپ‌تاپ:** روی شبکه خانه (TCP + توکن)، پیدا کردن خودکار، دکمه فایروال، نمایش صفحه استراحت روی لپ‌تاپ، فرستادن نوتیف‌های لپ‌تاپ.
- **پنجره تنظیمات** (customtkinter، هم‌رنگ برنامه‌های دیگر)، **فارسی و انگلیسی**، **نصب‌کننده** Inno Setup (مسیر نصب را می‌پرسد) + نسخه بدون نصب.
- **ساخت خودکار:** هر push به `main` → تست‌ها ← ساخت ← self-test ← نصب‌کننده ← نسخه خودکار ← Release.

### مشکل مهمی که حل شد (v1.7)

کرش‌های گاه‌وبی‌گاه: خواندن فهرست برنامه‌های آهنگ از API رسانه ویندوز (WinRT) از چند thread مختلف (خطای `0x8001010e`)، به‌علاوه اینکه سرویس رسانه ویندوز گاهی **اصلا جواب نمی‌دهد** و thread منتظر برای همیشه قفل می‌ماند. راه‌حل: `deskpresence/winrt_thread.py` — همه فراخوانی‌های WinRT روی یک thread با timeout که عملیات گیرکرده را رها می‌کند (لغو کردنش هم گیر می‌کند).

### نکته‌های باز (ویندوز)

- روی این کامپیوتر سرویس رسانه ویندوز (`GlobalSystemMediaTransportControlsSessionManager.RequestAsync`) هنگام تست جواب نمی‌داد؛ برنامه دیگر قفل نمی‌شود، ولی ممکن است آهنگ متوقف نشود. معمولا با ری‌استارت ویندوز درست می‌شود. اگر تکرار شد، بررسی بیشتر لازم است.
- تشخیص تماس از روی متن نوتیف Phone Link است و با تماس واقعی تست نشده.
- دقت دنبال کردن چشم در کالیبراسیون واقعی حدود ۱۰۷ پیکسل بود.
- تست برد بلوتوث گوشی («Usef's A15») در زمان تست جواب نداد (احتمالا بلوتوث گوشی خاموش بود).
- گزارش کرش لپ‌تاپ (کلیک روی «امتحان») هنوز علتش پیدا نشده؛ از v1.5 به بعد همه خطاها در `log.txt` و `crash.txt` ثبت می‌شوند. فایل‌های لپ‌تاپ را بفرستید.

## ۲. کار موبایل (برنچ `mobile-app`)

### چه چیزی ساخته شده

**برنامه اندروید** (`android/`، Kotlin + Jetpack Compose، فارسی و انگلیسی، رنگ‌بندی برند):
- نمایش «در حال کار / اینجا نیست / در حال استراحت»، تعداد لیوان آب و ساعت کار امروز.
- دیدن زنده وبکم؛ روی مانیتور نوشته می‌شود چه کسی در حال تماشاست.
- ارسال پیام به کامپیوتر.
- اتصال با **QR**، **لینک** یا **کد ۶ رقمی**؛ پیدا کردن خودکار کامپیوتر روی وای‌فای (mDNS).
- تب **افراد**: اتصال دو گوشی (دعوت/پیوستن با QR، کد یا لینک) و نمایش وضعیت همدیگر: وضعیت دلخواه، باتری، در حال تماس، آخرین فعالیت؛ هر ۱۵ دقیقه حتی با برنامه بسته (WorkManager).
- انتخاب خودکار مسیر: وای‌فای خانه اگر در دسترس باشد، وگرنه سرور واسط.

**سمت کامپیوتر:**
- `deskpresence/companion.py` — سرور HTTPS (گواهی خودامضا + pin در گوشی)، جفت‌سازی با کد یک‌بارمصرف ۱۰ دقیقه‌ای، توکن جدا برای هر گوشی (فقط hash ذخیره می‌شود)، استریم MJPEG وبکم، پیام.
- `deskpresence/e2e.py` — رمزنگاری سرتاسری P-256 ECDH + HKDF + AES-256-GCM با محافظت در برابر تکرار (replay).
- `deskpresence/relay_client.py` — اتصال دائمی WebSocket به سرور واسط.
- `deskpresence/stats.py` — آمار روزانه آب و ساعت کار.
- تنظیمات ← موبایل: روشن/خاموش، ساخت کد، QR، کپی لینک، آدرس سرور واسط، فهرست گوشی‌ها (تغییر نام، اجازه وبکم، حذف).

**سرور واسط** (`relay/`):
- aiohttp + SQLite، Docker + Caddy (HTTPS خودکار)، نصب با یک دستور (`relay/install.sh`)، راهنمای فارسی با تنظیم DNS ابر آروان (`relay/README.md`).
- فقط بسته‌های رمزشده را جابه‌جا می‌کند؛ تصویر، پیام و وضعیت را نمی‌بیند.

### وضعیت تست

- ۵۱ تست خودکار روی برنچ `mobile-app` پاس می‌شوند، از جمله تست سرتاسری واقعی: سرور واسط + کامپیوتر + گوشی شبیه‌سازی‌شده (جفت‌سازی، وضعیت رمزشده، پیام، استریم رمزشده وبکم، رد درخواست تکراری و کلید اشتباه، اشتراک وضعیت بین دو گوشی).
- برنامه اندروید در CI کامپایل شد (APK در Release نسخه v1.6.27)، ولی **روی گوشی واقعی اجرا نشده**.
- QR روی صفحه تنظیمات درست به لینک decode می‌شود.

### برگرداندن کار موبایل به `main`

<div dir="ltr">

```bash
git checkout main
git revert 59cfb98        # undo "Move the Android app and the relay server to the mobile-app branch"
git merge mobile-app      # usually nothing new, mobile-app == the reverted state
```

</div>

بعد از برگرداندن، این‌ها را دوباره بررسی کنید:
- `MediaController` در برنچ موبایل هنوز نسخه قدیمی (بدون `winrt_thread`) است؛ بعد از revert، کد `main` (نسخه درست‌شده) باقی می‌ماند، ولی هر تغییری که در `mobile-app` روی media/phone/calls باشد باید با الگوی `winrt_thread` هماهنگ شود.
- `calls.py` در `mobile-app` هنوز متن نوتیف‌ها را لاگ می‌کند (مشکل حریم خصوصی که در `main` حل شد) — هنگام merge نسخه `main` را نگه دارید.
- نسخه (`VERSION`) را بالاتر از آخرین Release بگذارید.

## ۳. مشکل سرور (اتصال بیرون از شبکه خانه)

### هدف

گوشی از بیرون خانه (اینترنت موبایل، وای‌فای دیگر) به کامپیوتر وصل شود، و گوشی‌ها وضعیتشان را برای هم بفرستند.

### راه ساخته‌شده: سرور واسط روی VPS (پیشنهادی)

همه دستگاه‌ها فقط به سمت سرور وصل می‌شوند، پس پشت هر مودم و CGNAT کار می‌کند و آدرس ثابت است. اشتراک وضعیت بین گوشی‌ها حتی وقتی کامپیوتر خاموش است کار می‌کند.

کارهای باقی‌مانده:
1. در ابر آروان رکورد **A** با نام `deskpresence` و آی‌پی VPS (پروکسی/ابر نارنجی **خاموش**).
2. روی VPS:

<div dir="ltr">

```bash
curl -fsSL https://raw.githubusercontent.com/Jolly-Panda-Works/DeskPresence/mobile-app/relay/install.sh | sudo bash -s deskpresence.useffarahmand.com
```

</div>

   (توجه: تا وقتی کار موبایل به `main` برنگشته، آدرس اسکریپت از برنچ `mobile-app` است و اسکریپت هم پیش‌فرض `main` را clone می‌کند — قبل از نصب، `REPO`/برنچ در `install.sh` را اصلاح کنید یا اول کار موبایل را به `main` برگردانید.)
3. در تنظیمات کامپیوتر ← موبایل ← آدرس سرور واسط: `https://deskpresence.useffarahmand.com`.

### راه پرسیده‌شده: خود کامپیوتر به‌عنوان سرور (بدون VPS)

ممکن است، ولی به شرایط اینترنت خانه بستگی دارد. چیزهایی که بررسی شد:

| مورد | نتیجه |
|---|---|
| IP عمومی دیده‌شده از بیرون | `5.45.75.87` — متعلق به **VPN** (Scalaxy، هلند)، نه اینترنت خانه |
| VPN | WireSock؛ مسیر پیش‌فرض همه ترافیک از VPN می‌گذرد |
| مودم/روتر | `192.168.100.1` — به UPnP جواب نداد (باز کردن خودکار پورت ممکن نیست) |
| دامنه | `useffarahmand.com` روی DNS ابر آروان (نه Cloudflare) |
| IP خانه از طرف ISP | **نامعلوم** |

شرایط لازم برای این راه:
1. **IP عمومی از ISP** (بدون CGNAT). اگر WAN IP مودم با `10.`، `100.64`–`100.127`، `172.16`–`172.31` یا `192.168.` شروع شود، CGNAT است و این راه **ممکن نیست**.
2. **باز کردن دستی پورت** روی مودم (Port forwarding) به کامپیوتر.
3. **IP متغیر:** به‌روزرسانی خودکار رکورد DNS در ابر آروان با API (کلید API آروان لازم است).
4. **VPN:** پاسخ کامپیوتر از مسیر VPN می‌رود و اتصال برقرار نمی‌شود؛ باید DeskPresence از VPN مستثنا شود (split tunneling) یا VPN خاموش باشد.
5. **محدودیت:** وقتی کامپیوتر خاموش/در sleep است، گوشی‌ها وضعیت همدیگر را هم نمی‌بینند.

### سوال‌های باز برای ادامه

- WAN IP در صفحه وضعیت مودم (`http://192.168.100.1`) چیست؟
- نوع اینترنت خانه: فیبر، ADSL/VDSL یا TD-LTE؟
- آیا می‌شود DeskPresence را در WireSock از VPN مستثنا کرد؟
- VPS در دسترس است یا نه؟

اگر جواب‌ها مثبت باشد، «حالت سرور خانگی» قابل ساخت است: همان سرور `companion` با پورت باز روی مودم + به‌روزرسانی خودکار DNS آروان + اشتراک وضعیت بین گوشی‌ها روی خود کامپیوتر.

## ۴. تصمیم‌های در انتظار

1. **کلید امضای APK:** بدون کلید ثابت، نسخه جدید روی نسخه قبلی نصب نمی‌شود. پیشنهاد: ساخت keystore با `keytool` در `F:\Jolly Panda Studio\- KEY\` و افزودن ۴ secret به مخزن (`ANDROID_KEYSTORE_BASE64`، `ANDROID_KEYSTORE_PASSWORD`، `ANDROID_KEY_ALIAS`، `ANDROID_KEY_PASSWORD`). CI از قبل آماده استفاده از آن‌هاست.
2. **Android SDK روی این کامپیوتر** (حدود ۱ گیگابایت، پذیرش لایسنس گوگل) برای ساخت و تست محلی.
3. **Dependabot:** چند PR باز دارد (به‌روزرسانی pytest، winrt و actions) — بررسی و merge یا بستن.
4. **لوگو:** راهنمای طراحی در `docs/LOGO_BRIEF.md`؛ منتظر فایل نهایی ۱۰۲۴×۱۰۲۴.

## ۵. یادداشت‌های فنی برای ادامه کار

- **محیط تست:** Python 3.12 (همان CI). اجرای تست‌ها: `python -m pytest -q` (روی `main` ۴۴ تست، روی `mobile-app` ۵۱ تست). Self-test برنامه ساخته‌شده: `DeskPresence.exe --self-test`.
- **نسخه‌گذاری:** `VERSION` = MAJOR.MINOR؛ CI شماره run را اضافه می‌کند (مثلا 1.7.29).
- **فایل‌های کاربر:** `%APPDATA%\DeskPresence\` — `config.json`، `log.txt`، `crash.txt` (از v1.5)، و در نسخه موبایل `stats.json`، گواهی‌ها و کلید `pc_identity.pem`.
- **اصل مهم WinRT:** هر فراخوانی جدید API ویندوز (رسانه، بلوتوث، …) باید از طریق `winrt_thread.run()` / `guarded()` انجام شود، نه `asyncio.run` در threadهای مختلف.
